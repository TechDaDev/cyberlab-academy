# CyberLab Academy

Mission-based cybersecurity education and simulation platform.

## Project status
- Milestone 01A–01D: identity, access and platform foundation — implemented and locally verified.
- Milestone 02A: academic catalog backend (courses, modules, lessons, objectives, resources,
  draft/publish lifecycle) — accepted and merged.
- Milestone 02B: classes, instructor assignments, student enrollment and relationship-based
  lesson access — backend implemented; frontend and later phases pending.
- Milestone 02C: version-aware lesson completion and derived progress — implementation in review
  (PR #12); frontend and later phases pending.
- Milestone 03: practical challenges for real local Kali Linux — architecture proposed, not
  implemented. Students run Kali on college laboratory computers (dual boot); CyberLab Academy
  manages assignments, verification, scoring, reporting and audit. See
  [`docs/CYBERLAB_MILESTONE_03_ARCHITECTURE.md`](docs/CYBERLAB_MILESTONE_03_ARCHITECTURE.md).

The earlier plan to simulate Kali Linux in the browser is superseded by the approved local-Kali
architecture. Browser-based educational simulation unrelated to Kali may still be developed later.

The API contract is generated by the backend and committed to
[`shared-contracts/openapi.json`](shared-contracts/openapi.json). Frontend work targets that
contract, not guessed endpoints.

## Architecture
- `frontend/`: Next.js, TypeScript, Tailwind CSS, shadcn/ui.
- `backend/`: Python FastAPI, PostgreSQL, Alembic.
- `simulation-engine/`: TypeScript, deterministic browser simulation for non-Kali educational content;
  not a practical-challenge runtime.
- `mission-content/`: Original, versioned module/mission data.
- `shared-contracts/`: OpenAPI and shared JSON schemas.
- `infrastructure/`: Local development and deployment configuration.
- `docs/`: Architecture, roles, security, milestone reports and implementation plans.

Student Kali Linux runs locally on laboratory computers. The college server does not host, stream or
control Kali and never executes student-submitted commands. Optional central training targets run on
an isolated laboratory network with trusted server-side verification. Practical scores derive from
server-authoritative awards and audited adjustments and remain separate from lesson progress.
